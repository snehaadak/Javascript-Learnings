
- **Without Promises**
    - lets consider a E-commerce website's small functionality which use APIs as an eg: Where we have a cart and once we have a cart and to move further with buying firstly the order is created which generates the orderId and that order ID further is used to proceed with payment so below would be the code:

        const cart = ["Nike Jordans" ,"Onitsuka Tigers", "Puma Seudes", "Addidas Sambas"]
        createOrder(cart)    //This create order API takes in the cart value and gives us the OrderID
        proceedToPay(orderID)  //This API further uses the above created orderID to move ahead with payment

    - The above two APIs (createOrder & proceedToPay) are asynchronous and are dependent on each other and hence we used to use callbacks to make them dependent.Hence will be the actual code for the above working.

        createOrder(cart, function(){
            proceedToPay(orderID)
        })

    - But we will face the very major issue with the above code and thta would be `Inversion of Control`. i.e we give the control of our callback function to the createOrder API and dependent, trust on it to make proceedToPay run further.

    - Hers's where promises come into picture to solve the above problem.


- **With Promises**

    - We design our createOrder API in such a way that it only takes in the cart as an argument and further returns a promise.

    - The way to create a promise is to declare it with the varible. for Eg: 

        const promise = createOrder(cart)

        whenever the above line is executed by javascript the createOrder api will return a promise.

    - *Promise is nothing but we can assume it to be an empty object with some data value in it {data}.* And this data value will hold whatever the createOrder API will return.

    - As we know createOrder API is going to perfom an async function hence it is going to take some time to be executed so initially when the code eecution hits the line: const promise = createOrder(cart)
    at very initial state the promise would be stored as {data: undefined} because the returned data from createOrder API is yet to be received. And assume after 3 to 5 sec we receive the data from createOrder API then that undefined would be replaced by our actual Order ID.

    - To move ahaead with our order functionality we need to attach a callback function (proceedToPay) to this promise object

        promise.then(function(){
            proceedToPay(orderID)
        });

    - once we have the data from in the promise object in previous step the next step where this object is attached to a callback function these. callback function automatically gets executed next.

    - The above proise and its callback function can also be written in one more below way:

        createOrder(cart).then(function(){
            proceedToPay(orderID)
        })


- **Callback VS Promise**

    - when we were providing the the proceedToPay call back function to the createOrder API we were giving the whole control of our callback function to that one API and were blindly trusting it to be executed.

    - In case of promise we are attaching our callback function to the promise object. where the control of proceedToPay is just with us. Also the createOrder API will have only on single job to return the ORder ID that is stored inside the promise object that is attached to the callback function ahead

- **Realife Eg**
    const GITHUB_API = "GitHub's get user details API"
    const user = fetch(GITHUB_API)   *//fetch returns a promis that is stored in user object*
    user.then(function(data){
        console.log(data)
    })                              *//This is the callback function attached to promise that would be executed once data is received in the user object*

- **States of Promises**
    - Promises can only have three states that is 
        1. pending: Its still in execution state. Initial state
        2. fullfilled: Operation was completed Successfully
        3. Rejected:when the operation fails

- About promises:
    - Promises are immutable. which means once we have the data in our promise object it can not be changed directly.

- **What is a Promise?**
    - *`It is an object representing the eventual completion or failure of an asynchronous operation`* or 
    *`Promise is placeholder that will be filled later with a value`* or
    *`A container for a future value`* 
    - Promises solve the issue of inverion control.

- **Promise Chaining**
    - As we had one more problem with using callbacks and that was callback hell. whcih could be resolved with Promise Chaining.
    - for below piece of callback Hell:
        createOrder(cart,function(OrderID){
                proceedPayment(function(paymentInfo){
                    showOrderSummary(function(){
                        updateWallet()
                    })
                })
            })

        here's the promise chain way to write, to return or the data that is received in first promise for that data to be flowed down the pipeline it is required to return our callbacks:
            createOrder(cart)
                .then(function(OrderID){
                   return proceedPayment(OrderID)})
                .then(function(paymentInfo){
                   return showOrderSummary(paymentInfo)})
                .then(function(paymentInfo){
                    return updateWallet(paymentInfo)})

        -  the above piece of code of promise chain can also be written using arrow functions which is more readable:
            createOrder(cart)
                .then((orderId) => proceedPayment(orderId))
                .then((paymentInfo) => showOrderSummary(paymentInfo))
                .then((paymentInfo) => updateWallet(paymentInfo))
