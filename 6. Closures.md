
- **Closure**
    - A Closure is the combination of a function bundled together(enclosed) with references to its surrounding state(lexical environment) or Closure means a function bind together with its lexical environment
    - In other words, a closure gives you access to another function's scope from an inner function.
    - for eg:
        function x(){
            var a = 7;
            function y(){
                console.log(a);
            }
            y();
        }
        x();

    y forms a closure because it is binded with the variable of its lexical scope (function x). i.e. variable a

- **Closure Explaination**
    - For above piece of information about we return the inner function ad storng it to the another variable and later calling it as a function it remembers the inner function with its lexical environmnet anywhere.
    - for eg as we stored the x(); but according to the javascript as soon we hit the return y inside the x(); the execution context of x(); is deleted completely from the call stack. but what if we call the z(); later sometime anywhere in our code after 1000's of line of code....
        z();       --> [ 7 ]
        the z function when called sometime later will always return the value 7 because this is what closures are they store the inner functions and it lexical environment stored as a closure. 

    - when the function are returned from another funtion (in our example y returned from x) they still remember there lexical environment where they were actually present. hence tho x no longer exits yet y function remebers its lexical environment.

- **setTimeout**
    - function x() {
        var i = 1;
        setTimeout(function(){
            console.log(i);
        }, 3000);
        console.log("Hello World!")
    }
    x();
    -  In above piece of code the setTimeout function forms the closure and and saves up its lexical environment's reference to variable i. when the above code is executed as the setTimeout function is set to 3000ms (3sec) it stores it as a closure with the reference to var i and moves ahead with the rest of the code and hence first prints Hello world! and then after 3 secs again the setTimeout function is pushed into callstack and executed printing 1.

    - Now let's consider one more example: if we are asked to print 1 to 5 after every 1, 2 ,3 and so on sec each. just using for loop like below won't work: because the it stores the reference to i and not actually i by the time the timer is about to end the for loop has already executed completely in back end and var value has already changed to 6 and hence 6 is printed 5 times.

    x();

    to correct the above code we use let instead of var because let is block scoped and it creates a new reference of i for each execution.

    if not by using let we pack the settimeout closure in other closure and call it in the for loop. which creates a new instance of i at every new call.

- **Disadvantages of Closure**
    - There could be over conssumption of memory due to closures. because everytime a closure is created it is stored the variables are allocated memory somewhere. and this variables are not `Garbage Collected` till the program expires.
    - If not handled properly it could lead to `Memory Leak`. because this variables are accumulated in the memory and which could lead to freezing of browser.

    *`Garbage collector` is the program in  the browser or the JS engine that free's up the unutilised memory*
