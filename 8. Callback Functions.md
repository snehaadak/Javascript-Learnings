
- **Javascript: Synchronous Single Threaded Language**
    - As javascript has just one single call stack which is also known as main thread. Hence it is called single threaded language
    - As javscript runs the code line by line and executes it. it is a synchronous language.


- **Callback Functions in Javascript**
    - As we know we can use afunctions as values, or arguments. so the dunctions that we use to pass into another functions are the callback functions.
    - Callback functions gives us access to the asynchronous world in javascript.
    - for eg: function x(param1){

              }

              x(function y(){ })
         
        y is a callback function because it is completely dependent on the the function x when it would be called sometime later in the code further. 
    
    - setTimeout(function a(){}, time in ms) as an example of callback function where function a is a callback function which is expected to be called after the timer has ended. setTimeout will take a callback function and store it in separate space and attach a timer to it. But javascript won't wait for the timer to go off and rather move to the next line of code. *Hence we say the callback function give us the power of asynchronous world where it wont wait for the timer to get over and then move to the next line of code rather it will start the timer and move directly to the next piece of code until the timer is over and then the setTimeout would be pushed in the callstack after the timer is over*


- **Blocking the main thread**
    - Every operation that happens on our page happens via callstack. So any specific operation that is blocking the js callstack it is known as blocking the main thread. 
    - for eg if we have a function x that has some heavy operation to be performned which takes up around 20 to 30secs to be done. This will block our call stack and as javascript has just one callstack it wont be able to move further with the code.
    -  Hence we should try to use the async operations for the ones that are time consuming instead of blocking our main thread.


- **Event Listeners**
    - Event listeners also use the callback functions as the parameters.
    - for eg:
        document.getElementById("button'sID").addEventListener("click",function(){
            something that you have to do only on click
        })
    When js is executing and it comes across a event listener it will attach it to the button with that id and set a call back function for it and stores it in some place and automatically comes into our call stack as soon as the event happens.

- **Why do we remove event listeners**
    - Event listeners are heavy which means they take up the memory because they are forming closures with functions. and hence this event listener's memory couldn't be freed up.
    - If we have alot of amout of event listeners on a page which might take up alot of memeory and slow down our pages.
    - Hence it is the best practise to free up the space by removing the eventListener
