
- **Block**
    - A block is defined by curly braces `{}`. this is a block. It is also known as `Compound Statement`
    - {
        *// A Block or a Compound Statement*
      }
    - A block is used to combine multiple javascript statements all together to form one group. We use grouping of statements so that we can use these multiple statement's group (block) where in javascript expects only single statement.
    - for eg:
        a if condition takes in a single statement to be performed on condition so we can use a block for this purpose.
            if (condition) {
                *use below blocked statements to perfomr further set of actions all together*
                do so n so
                console.log(XYZ) 
            };


- **Block Scope**
    - Block Scope means what all variables and functions we can access inside a block
    - For Eg: we will declare and initialize the three types of variables inside a block and observe there working.
        {
            var a = 10;
            let b = 100;
            const c = 1000;
        }

        for above piece of code during the memory allocation phase the memory to the var a is allocated or hoisted in the global scope. whereas the let and const are allocated or hoisted inside the block which is a separate memory allocation space. *Hence, let & const are called as blocked scoped because they are stored in separate memory space called block*
    - Once the block execution is completed this let & const varibales are no more accesible. which means we can not access this let and const outside the specific block they are declared in. for eg:
        {
            var a = 10;
            let b = 100;
            const c = 1000;
            console.log(a);         --> [ 10 ]
            console.log(b);         --> [ 100 ]
            console.log(c);         --> [ 1000 ]
        };
            console.log(a);         --> [ 10 ]
            console.log(b);         --> [ Reference Error: b not defined ]
            console.log(c);         --> [ Reference Error: c not defined ]

- **Shadowing**
    - If we have a same named variable outside a block in the global scope and inside the block as well and we try to access that variable inside the block itself it will use the block initialized value. and even if we try to access the value in the global scope scope it will still revert us the block's value.
    - for eg:
        var a = 10;
        {
            var a = 100;
            console.log(a);         --> [ 100 ]
        }
            console.log(a);         --> [ 100 ]
    - Hence we can say that the variable declared inside the block shadowed the same varibale values decalred outside of it.
    - These happens because for var it points to the same memory location inside the global scope. and the block's value replaces our previously declared value.
    - Incase of let and const it doesnt work that way.
        let b = 1;
        const c = 10;
        {
            let b = 100;
            const c = 1000;
            console.log(b);         --> [ 100 ]
            console.log(c);         --> [ 1000 ]
        }
        console.log(b);         --> [ 1 ]
        console.log(c);         --> [ 10 ]

    In above case the b and c declared inside of th block couldn't be accesed outside the block hence shadowing doesnt work here and it picks up on the values set in the global scope.
    - *Shadowing behaves the same inside the function as it behaves in the block.*
